# 汽车集团车主权益与售后履约平台

**角色**　Java 后端开发，基于 hmdp-plus 二次开发，负责预约履约模块及并发验证

**技术栈**　Java 17、Spring Boot、MySQL、Redis、Redisson、Caffeine、Lua、Kafka、ShardingSphere、JUnit、k6

**项目描述**　面向汽车集团车主关怀活动，支持统一投放保养券、车主抢券后跨网点预约及到店核销，并在网点临时停约时支持自行改期、分批取消及券权益恢复。

- **活动查询与抢券。** 门店详情采用 Cache Aside、布隆过滤器、带 TTL 的空值缓存和 Redisson 锁内二次检查，减少无效查询与热点重复回源。券详情采用 Caffeine + Redis 两级缓存，抢券入口按用户和 IP 限流，并校验一次性令牌。
- **异步下单与权益登记。** 使用 Redis + Lua 原子校验活动状态、库存及重复购买并预扣库存，Kafka 异步落单，ShardingSphere 路由交易数据。消息发送或消费失败时触发 Redis 库存返还，预约侧按已落库订单登记权益，以订单主键防止重复登记。
- **跨店改期与并发一致性。** 主动改期使用 MySQL 本地事务一次完成新工位占用、旧工位释放和预约版本更新，目标满位或写入失败时保留原预约。业务变更与请求幂等记录同事务提交，核销校验预约版本和网点归属。10 项 JUnit 回归通过（含 8 项真实 MySQL 场景），8 路同键并发重试仅占用 1 个工位。本地 k6 目标 250 请求/秒时，单热点与 20 时段分散写入的成功请求 P95 分别为 653.25 ms 和 27.49 ms，单热点组有 736 个请求未发出。结合 MySQL 锁等待采样定位到时段容量的写入竞争。
- **停约改派与权益恢复。** 基于预约与容量的一致性快照，将车主和候选时段建模为容量约束二分图。发邀采用候选较少的车主优先的贪心策略，按实时容量复核后生成 5 分钟占位。过期占位由定时任务回收，店员可对停约时段分批取消，释放原工位及待确认占位、恢复券权益并记录原因。在 9,000 笔容量紧张的本地合成预约中，贪心策略的可安排率由最近优先的 85.63% 提至 89.93%，最大流对照达到 96.44%。
